# 手势状态机与界面接入

本模块是无 HAL、RTOS、LVGL 依赖的 C99 业务逻辑，使用调用者提供的固定大小上下文，无动态内存分配。它只处理识别结果，不执行神经网络推理；六类候选仍需实板业务验收，原始五类模型或模拟数据不能证明真实手势可用。

## 类别与方向

类别顺序必须与已验收模型包一致：

| 类别 | 逻辑动作 |
| --- | --- |
| `POINT_LEFT` | `PREVIOUS`：上一页／上一个目录条目 |
| `POINT_RIGHT` | `NEXT`：下一页／下一个目录条目 |
| `FIST` | `BACK`：返回目录 |
| `PALM` | `CONFIRM`：进入当前目录条目 |
| `V_SIGN` | `PLAY_PAUSE`：切换轮播播放状态 |
| `UNKNOWN` | 非目标类，不发命令；连续稳定时允许下一次动作 |

左右以原始传感器图像为准。预览镜像只改变显示坐标，不能交换运行时逻辑动作；训练图片水平翻转时必须同步交换左右标签。

## 默认门槛

`gs_gesture_init(context, NULL)` 使用下表默认值；可传入独立的 `gs_gesture_config_t` 调整，不能在运行中直接改上下文字段。

| 检查 | 初始值 |
| --- | --- |
| 目标类最高分 | ≥ 0.90 |
| 第一、第二类分差 | ≥ 0.20 |
| UNKNOWN 最高分 | ≥ 0.95 |
| 同一目标持续确认 | ≥ 400 ms **且** ≥ 3 张新帧 |
| 连续 UNKNOWN 中性区间 | ≥ 600 ms **且** ≥ 4 张新帧 |
| 相邻新推理结果接收间隔、采集时间间隔 | 均 ≤ 350 ms |
| 完整图像年龄 | ≤ 300 ms |

输入 `scores[6]` 必须是有限、归一化的分数，不能是原始 INT8 值或 logits；模块检查各项在 0～1、总和在 0.99～1.01。分数不是已验证的操作成功概率。UNKNOWN 合并旧 OTHER 与 EMPTY，不能证明物理撤手；其他手形也可能满足解除动作锁定条件。

## 状态与中性区间

初始化为 `Disabled`。请求启用后，首张有效新图进入 `WaitClear`；启动时已摆出的手势不会直接执行。UNKNOWN 中性区间条件满足后进入 `Ready`，目标通过门槛后进入 `Candidate`。保持条件满足时输出一次命令，立即回到 `WaitClear`。长时间保持目标姿势不能再次发命令，但稳定的其他手形可能解除锁定。

候选类别变化、UNKNOWN 或低分会清除候选。图像无效、超龄、顺序异常和停帧会清除两种证据并进入 `Disabled`；恢复后必须重新取得中性证据。黑帧、过曝、读取错误和模型契约失败应设置 `observation.valid = false`，不能转成 UNKNOWN。

## 时基与帧身份

- `capture_ms` 使用完整帧实际完成时的毫秒时间戳；`now_ms`、相机、GUI 都用同一时基，当前 App 使用 `HAL_GetTick()`。
- 证据持续时间只由已接受帧的采集时间累计。重复 `frame_id` 不增加帧数；`gs_gesture_progress()` 也不因 GUI 刷新而增长。
- `frame_id` 单调递增，可跳号，支持 `uint32_t` 自然回绕；相机故障重启不能将它归零。新帧采集时间也必须前进。
- 无符号差值支持毫秒计数回绕，所有比较区间必须小于 `2^31` ms。故障截止时间等上层历史标记必须及时失效，不能永久保留为比较基准。

## 应用集成约定

1. 在调度器已运行的默认启动任务中执行 `gs_app_init()`，BSP及可能依赖HAL tick的初始化保持在调度锁外；六个业务任务的创建和全部句柄发布才使用启动门禁，随后恢复调度。不能移回启动调度器之前，以免HAL_Delay受BASEPRI屏蔽而卡死。GestureTask唯一拥有手势上下文，GuiTask唯一拥有 `gs_ui_t` 和显示对象；其他任务通过队列／线程标志请求操作。
2. 仅在模型契约通过并且用户请求开启时调用 `gs_gesture_set_enabled(..., true)`；重复传入相同开关值不会重置状态。即使没有图像，也要周期调用 `gs_gesture_tick()`，使停帧及时失效。
3. CameraTask 显式上报相机故障。清空已入队观察值后，还要使用采集时间截止点或输入代际排除 VisionTask 中仍在处理的故障前图像。
4. 将最新 UI 代际传给 `tick/process`。候选锁存代际，期间页面、模式或操作含义改变会使候选作废并要求撤手。普通重绘和轮播进度刷新不变更代际；真正换页会变更。
5. `gs_gesture_process()` 返回 `true` 时将完整命令入队，保留 `sequence` 和 `ui_generation`。队列满则丢弃该命令并保持撤手要求，不能重新编号重放。
6. GuiTask 出队后立即调用 `gs_ui_execute()`，由其顺序完成序号去重、代际检查、动作可用性检查与业务更新。`GS_UI_REJECTED_STALE` 要通知 GestureTask 重新撤手，不能给旧命令补上新代际再执行。触摸／按键使用 `gs_ui_local_action()`。
7. 一个 UI 实例对应一条手势命令序列。若重新初始化命令生产者，必须同时排空旧命令并重置接收端序号状态。诊断字段只是观测副本，不能作为可随意修改的业务控制状态。

`Modules/Ui` 提供目录、阅读与自动轮播模型：目录禁用播放／暂停，手动翻页在边界禁用，轮播到末页后回到第一页。暂停只影响轮播，不关闭相机或识别。显示适配层负责把这些状态绘制到实际屏幕。

## 已验证范围

`Tests/test_gesture_ui.c` 的 17 组宿主测试覆盖撤手、持势去重、时间／帧数门槛、异常恢复、页面代际、命令重放、计数回绕、目录阅读轮播及暂停后继续输入。MSVC 使用 `/std:c11 /W4 /WX` 编译并全部通过；源码保持 C99 兼容。测试输入是人工构造的分类分数，不能代替模型准确率、实物画面或板端时序验收。
